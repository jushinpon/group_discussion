# 0006 — 學生應產出自有數據；純文獻回顧不算研究進度

- 狀態：accepted
- 日期：2026-10-31
- 決策者：Pon

## 背景

回補 2023-08 起的完整信件後發現：student-01（博二，120 封）與student-02（博三，58 封／71 場報告）
在**兩到三年、178 封進度信**中，沒有一筆自己的計算或實驗結果——會議投影片標題頁一律是
"Paper review"。

在建立每週進度分析時，必須先回答一個語意問題：**「有寄信、有報告」算不算有進度？**
這個答案會決定三態判定（on-track / at-risk / off-track）的基準，所以不能由 agent 自行假設。

## 決策

Pon 2026-10-31 明確回答：**學生應該產出自己的數據。**

因此：

1. `progress` 這個 verdict 只代表「這是一封進度信」，**不代表有推進**。
   純文獻回顧的週報歸類為 `progress`，但筆記必須註明「本封為文獻研讀，非自有成果」。
2. 週進度分析中，**「自有數據的產出」是首要判準**；連續多週只有 paper review 即為
   `at-risk`，不論信件多準時、投影片多精美。
3. 每條 `goals.md` 的「對照現況」必須以「有無自有數據／可驗證產出」回答，
   不能以「有寄信」「有報告」代替。
4. 學生自己的文字（投影片上的 H1/H2、批判註記）算**理解**，不算**產出**；
   兩者在 wiki 中分開記錄，不得混為一談。

## 後果

- 一位學生可能「每週準時寄信、內容豐富」卻被判為落後——這是刻意設計，不是誤判。
- 若 Pon 對某位學生另有階段性要求（例如先做半年文獻），必須記在該學生的
  `students.yaml` 或 `goals.md` 中作為例外，不得由 agent 推測。
- 這條規則同時解釋了為什麼 `goals.md` 的目標必須寫成**可被否證**的形式：
  「做過什麼」與「交出什麼」必須能分辨。
