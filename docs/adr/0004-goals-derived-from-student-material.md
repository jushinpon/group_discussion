# Research goals are derived from student material, not gated on PI sign-off

`students/<slug>/goals.md` is generated by the agent from what the student has actually sent,
and is revised dynamically as new evidence arrives. Where a student supplies a proposal
(計畫書 — typically a PDF/PPTX attachment, e.g. 國科會 proposal drafts), the goals are taken
from the proposal's own aims rather than inferred from mail prose; the proposal wins over
anything the agent would otherwise have concluded.

Explicitly **not** adopted: a workflow where goals sit as a draft until Pon approves and lock
at `v1`. Pon's decision (2026-10-31) was that goals come from the material and stay editable,
so the system does not block on a human approval step to become useful.

## Consequences

- Progress analysis compares a student against a goal the agent derived. To keep that
  honest, every goal line carries its source (`Message-ID` or attachment filename + page)
  and a `derived | from-proposal` marker, so a wrong goal can be traced and corrected
  rather than silently grading the student against a fiction.
- Revision must be cheap: `goals.md` keeps a short revision history (date, what changed,
  why) so drift between weeks is visible in `git diff`.
- Pon's own mail is a goal input too (ADR-0005), so a PI instruction can override a
  student-stated aim without a separate approval ceremony.
